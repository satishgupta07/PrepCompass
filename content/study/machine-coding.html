Where does state live? Four rulesthe most-judged decision

  • 1 · Derive, do not duplicate. If it can be computed from other state (filtered list, total, “is valid”), compute it in render (useMemo only if costly). Two copies of one truth always drift apart.
  • 2 · Keep state as low as possible, lift to the nearest common parent only when two siblings need it.
  • 3 · Normalise relational data. Store byId maps plus id lists, not nested trees. Updating one card or comment then touches one place.
  • 4 · Server data is not UI state. Loading, error and cache belong in a fetching layer or hook, separate from open/closed or selected-tab state.

// Works controlled (value + onChange) or uncontrolled (defaultValue)
function useControllable({ value, defaultValue, onChange }) {
  const [inner, setInner] = useState(defaultValue)
  const controlled = value !== undefined
  const current = controlled ? value : inner
  const set = useCallback(next => {
    if (!controlled) setInner(next)
    onChange?.(next)
  }, [controlled, onChange])
  return [current, set]
}

Requirementsasked in 5+ loops

  • Type in an input, show matching suggestions from an async source after a short pause.
  • Arrow keys move the highlight, Enter selects, Escape closes, click selects.
  • Out of the box: debounce, cancel stale requests, a result cache, loading / empty / error states, highlight the matched text, accessible combobox semantics.
State designquery, items, status (idle | loading | error), open, active index. The cache is a useRef(Map): changing it must not re-render. Pass fetchSuggestions(query, signal) in as a prop so the component works with any API.

The componentworking code

function Autocomplete({ fetchSuggestions, onSelect, debounceMs = 300, minChars = 2 }) {
  const [query, setQuery]   = useState("")
  const [items, setItems]   = useState([])
  const [status, setStatus] = useState("idle")        // idle | loading | error
  const [open, setOpen]     = useState(false)
  const [active, setActive] = useState(-1)
  const cache  = useRef(new Map())
  const listId = useId()

  useEffect(() => {
    const q = query.trim()
    if (q.length < minChars) { setItems([]); setStatus("idle"); return }
    if (cache.current.has(q)) { setItems(cache.current.get(q)); setStatus("idle"); return }

    const ctrl = new AbortController()
    setStatus("loading")
    const t = setTimeout(async () => {
      try {
        const res = await fetchSuggestions(q, ctrl.signal)
        cache.current.set(q, res)
        setItems(res); setActive(-1); setStatus("idle")
      } catch (e) {
        if (e.name !== "AbortError") setStatus("error")
      }
    }, debounceMs)
    return () => { clearTimeout(t); ctrl.abort() }   // cancels debounce AND the stale request
  }, [query, minChars, debounceMs, fetchSuggestions])

  function choose(item) { setQuery(item.label); setOpen(false); onSelect?.(item) }

  function onKeyDown(e) {
    if (e.key === "ArrowDown") { e.preventDefault(); setOpen(true); setActive(i => Math.min(i + 1, items.length - 1)) }
    else if (e.key === "ArrowUp") { e.preventDefault(); setActive(i => Math.max(i - 1, 0)) }
    else if (e.key === "Enter" && open && items[active]) { e.preventDefault(); choose(items[active]) }
    else if (e.key === "Escape") setOpen(false)
  }

  return (
    <div className="ac">
      <input
        role="combobox" aria-autocomplete="list" aria-expanded={open}
        aria-controls={listId} aria-activedescendant={active >= 0 ? `${listId}-${active}` : undefined}
        value={query}
        onChange={e => { setQuery(e.target.value); setOpen(true) }}
        onKeyDown={onKeyDown}
        onFocus={() => setOpen(true)}
        onBlur={() => setOpen(false)}
      />
      {open && query.trim().length >= minChars && (
        <ul id={listId} role="listbox">
          {status === "loading" && <li className="muted">Searching…</li>}
          {status === "error"   && <li className="muted">Something went wrong</li>}
          {status === "idle" && items.length === 0 && <li className="muted">No results</li>}
          {items.map((it, i) => (
            <li key={it.id} id={`${listId}-${i}`} role="option" aria-selected={i === active}
                onMouseDown={e => { e.preventDefault(); choose(it) }}   // before blur closes the list
                onMouseEnter={() => setActive(i)}>
              <Highlight text={it.label} query={query} />
            </li>
          ))}
        </ul>
      )}
    </div>
  )
}

function Highlight({ text, query }) {
  const i = text.toLowerCase().indexOf(query.trim().toLowerCase())
  if (i < 0 || !query.trim()) return text
  return <>{text.slice(0, i)}<mark>{text.slice(i, i + query.trim().length)}</mark>{text.slice(i + query.trim().length)}</>
}

▶ Why onMouseDown and not onClick: the input loses focus (blur) before click fires, which would close the list and unmount the option before the click lands.

Edge cases and follow-upswhat gets probed

  • Race / stale response: cleanup aborts the previous request. If the API cannot be aborted, compare the response’s query with the current one before setting state.
  • Fast typing and caching: cache by trimmed, lower-cased query; cap the size (LRU) so memory does not grow forever.
  • Millions of records: the server does prefix search (a trie, or an index with ILIKE 'abc%') and returns the top 10. The client never filters a huge list.
  • Keyboard: scroll the active option into view (scrollIntoView({ block: "nearest" })); wrap around at the ends if asked.
  • IME and paste: composition events (CJK input) should not trigger search mid-composition.
  • Unstable-prop bug: fetchSuggestions must be stable (useCallback or defined outside), or the effect re-runs every render.
interview edgeThe scoring points are: debounce + abort, keyboard navigation, combobox ARIA, and the cache. Mentioning a server-side trie or index for huge datasets shows you think past the component. The system design version of this problem is the typeahead case study in the System Design notebook.

Remember!

  • Debounce + AbortController in the effect cleanup
  • Cache in a ref, not state
  • onMouseDown beats blur
  • combobox + listbox + aria-activedescendant

Requirementsasked in 4 loops

  • Load the first page, load the next automatically as the user nears the end, stop at the end of data.
  • Out of the box: no duplicate requests, cursor pagination, failed-page retry, a loading indicator, no duplicate items, and a plan for very long lists.
Say this“I put an invisible sentinel element below the list and watch it with an IntersectionObserver. When it comes into view I fetch the next page. I use a cursor rather than a page number so items inserted at the top do not shift pages and produce duplicates or gaps.”

The hook and the componentworking code

function useInfinite(fetchPage) {                    // fetchPage(cursor) → { data, nextCursor }
  const [items, setItems]   = useState([])
  const [status, setStatus] = useState("idle")        // idle | loading | error | done
  const cursor = useRef(null)
  const busy   = useRef(false)                        // blocks overlapping requests
  const seen   = useRef(new Set())                    // dedupe by id

  const loadMore = useCallback(async () => {
    if (busy.current) return
    busy.current = true
    setStatus("loading")
    try {
      const { data, nextCursor } = await fetchPage(cursor.current)
      const fresh = data.filter(x => !seen.current.has(x.id))
      fresh.forEach(x => seen.current.add(x.id))
      setItems(prev => [...prev, ...fresh])
      cursor.current = nextCursor
      setStatus(nextCursor ? "idle" : "done")
    } catch {
      setStatus("error")
    } finally {
      busy.current = false
    }
  }, [fetchPage])

  return { items, status, loadMore }
}

function Feed({ fetchPage }) {
  const { items, status, loadMore } = useInfinite(fetchPage)
  const sentinel = useRef(null)

  useEffect(() => {
    const el = sentinel.current
    if (!el || status !== "idle") return              // not while loading, failed or finished
    const io = new IntersectionObserver(
      ([entry]) => entry.isIntersecting && loadMore(),
      { rootMargin: "400px" }                          // start loading before it is visible
    )
    io.observe(el)
    return () => io.disconnect()
  }, [status, loadMore])

  return (
    <div>
      {items.map(p => <Post key={p.id} post={p} />)}
      {status === "loading" && <Skeleton />}
      {status === "error" && <button onClick={loadMore}>Failed to load. Retry</button>}
      {status === "done" && <p>You are all caught up</p>}
      {status === "idle" && <div ref={sentinel} aria-hidden="true" style={{ height: 1 }} />}
    </div>
  )
}

▶ Why the observer is re-created when status changes: if the new page is still short enough that the sentinel is on screen, a fresh observer fires immediately and keeps loading. The very first load works the same way (empty list, sentinel visible).

Edge cases and follow-upswhat gets probed

  • Failed page: status error removes the sentinel, so there is no retry loop; the user presses Retry (or auto-retry with backoff).
  • Offset vs cursor: with ?page=2, a new item at the top pushes everything down and page 2 repeats an old item. A cursor (?after=lastId) always continues from the right place.
  • 10,000+ items in the DOM get slow: virtualise (window the list), or keep only a bounded number of pages and drop far-away ones. See the virtualisation example in the React notebook.
  • Scroll restoration: when the user opens an item and comes back, keep the loaded pages (cache) and the scroll offset.
  • Scroll events instead of an observer need throttling and layout reads; IntersectionObserver does that off the main thread. Prefer it.
  • Accessibility: infinite scroll hurts keyboard users (the footer is unreachable) and screen-reader users. Offer a “Load more” button as an alternative, and announce new content politely.
  • New items at the top (“12 new posts”): show a pill the user clicks, do not shove content while they read.
interview edgeThe scoring points are: IntersectionObserver instead of scroll listeners, a busy guard, cursor pagination, error and end states, and what you do when the list gets huge. Say “dedupe by id” out loud; it shows you have seen the real bug.

Remember!

  • Sentinel + IntersectionObserver + rootMargin
  • Busy ref prevents duplicate requests
  • Cursor, not page number
  • Huge list → virtualise

Requirementsasked in 4 loops

  • A form split into steps, Next / Back, validation before moving on, a final review and submit.
  • Going Back must keep what the user typed.
  • Form engine version: the form is described by a schema (JSON) with dynamic fields, validation rules and conditional visibility, and one generic renderer draws it.
State designAll values live in one object in the parent (values), not inside each step, so unmounting a step loses nothing. Plus stepIndex, errors and touched. Whether a field is visible and whether a step is valid are derived, never stored.

function validateField(f, value) {
  const r = f.rules ?? {}
  const text = String(value ?? "").trim()
  if (r.required && !text) return `${f.label} is required`
  if (text && r.min && text.length < r.min) return `${f.label} needs at least ${r.min} characters`
  if (text && r.pattern && !r.pattern.test(text)) return r.message ?? `${f.label} is invalid`
  return null
}

function validateStep(step, values) {
  const errors = {}
  for (const f of step.fields) {
    if (f.showIf && !f.showIf(values)) continue            // hidden fields are not validated
    const msg = validateField(f, values[f.name])
    if (msg) errors[f.name] = msg
  }
  return errors
}

The engineworking code

function FormEngine({ schema, onSubmit }) {
  const [values, setValues]   = useState({})
  const [errors, setErrors]   = useState({})
  const [step, setStep]       = useState(0)
  const [submitting, setSubmitting] = useState(false)
  const current = schema.steps[step]
  const last = step === schema.steps.length - 1

  const setField = (name, value) => {
    setValues(v => ({ ...v, [name]: value }))
    setErrors(e => (e[name] ? { ...e, [name]: undefined } : e))   // clear that field's error on edit
  }

  async function next(e) {
    e.preventDefault()
    const errs = validateStep(current, values)
    setErrors(errs)
    if (Object.keys(errs).length) return                          // stay, show errors
    if (!last) return setStep(s => s + 1)

    setSubmitting(true)
    const visible = Object.fromEntries(                           // drop values of hidden fields
      schema.steps.flatMap(s => s.fields)
        .filter(f => !f.showIf || f.showIf(values))
        .map(f => [f.name, values[f.name]]))
    try { await onSubmit(visible) } finally { setSubmitting(false) }
  }

  return (
    <form onSubmit={next} noValidate>
      <p aria-live="polite">Step {step + 1} of {schema.steps.length}: {current.title}</p>
      {current.fields.map(f =>
        (!f.showIf || f.showIf(values)) && (
          <Field key={f.name} field={f} value={values[f.name] ?? ""} error={errors[f.name]}
                 onChange={v => setField(f.name, v)} />
        ))}
      <button type="button" disabled={step === 0} onClick={() => setStep(s => s - 1)}>Back</button>
      <button disabled={submitting}>{last ? (submitting ? "Saving…" : "Submit") : "Next"}</button>
    </form>
  )
}

function Field({ field, value, error, onChange }) {
  const id = useId()
  const common = { id, value, "aria-invalid": !!error, "aria-describedby": error ? id + "-err" : undefined,
                   onChange: e => onChange(e.target.value) }
  return (
    <div>
      <label htmlFor={id}>{field.label}</label>
      {field.type === "select"
        ? <select {...common}><option value="">Choose…</option>{field.options.map(o => <option key={o}>{o}</option>)}</select>
        : <input type={field.type} {...common} />}
      {error && <span id={id + "-err"} role="alert">{error}</span>}
    </div>
  )
}

Edge cases and follow-upswhat gets probed

  • Preserve data on Back: because values is held by the parent, steps can unmount freely. Persist to sessionStorage for refresh safety (and never persist passwords).
  • Jumping ahead: a step indicator should only let users click steps whose predecessors validated.
  • Double submit: disable the button while submitting; on the server use an idempotency key.
  • Server-side errors (“email already taken”) map back onto fields: setErrors(serverErrors), and focus the first invalid field.
  • Validate when? on blur first, then on change after the first error, and always on submit. Validating on every keystroke from the start is hostile.
  • Conditional fields: a field’s value should be cleared (or not submitted) when it becomes hidden.
  • Extensibility: a map of field type to component ({ text: TextInput, select: Select }) and a rules registry let you add a field type without touching the engine. Async validators (username availability) are debounced and cancellable.
  • Performance: a big form re-renders on each keystroke; memoise Field or use an uncontrolled approach (React Hook Form) and say why.
interview edgeThe scoring points are: state held above the steps, validation kept separate from UI, schema-driven rendering, conditional visibility and accessible error messages (aria-invalid, aria-describedby, focus the first error). Then name the production answer: “React Hook Form plus Zod”.

Remember!

  • One values object in the parent
  • Validation = pure functions on a schema
  • Hidden fields: do not validate or submit
  • Server errors map back to fields

Say this“I keep the upload logic outside React in a small queue class that knows nothing about the UI. It has a concurrency limit and emits changes. A hook subscribes to it and the component only renders. fetch cannot report upload progress, so I use XMLHttpRequest.”

The upload function and the queueworking code

function uploadFile(file, { onProgress, signal }) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest()
    xhr.open("POST", "/api/upload")
    xhr.upload.onprogress = e => e.lengthComputable && onProgress(Math.round((e.loaded / e.total) * 100))
    xhr.onload  = () => xhr.status < 300
      ? resolve(JSON.parse(xhr.responseText))
      : reject(Object.assign(new Error("HTTP " + xhr.status), { status: xhr.status }))
    xhr.onerror = () => reject(new Error("network"))
    signal.addEventListener("abort", () => { xhr.abort(); reject(new DOMException("Aborted", "AbortError")) })
    const body = new FormData(); body.append("file", file)
    xhr.send(body)
  })
}

const MAX_BYTES = 10 * 1024 * 1024
const ALLOWED = ["image/png", "image/jpeg", "application/pdf"]

class UploadQueue {
  items = []                                  // { id, file, status, progress, error, ctrl, tries }
  running = 0
  listeners = new Set()
  constructor(limit = 3) { this.limit = limit }

  subscribe = fn => { this.listeners.add(fn); return () => this.listeners.delete(fn) }
  emit() { this.snapshot = [...this.items]; this.listeners.forEach(l => l()) }
  snapshot = []

  add(files) {
    for (const file of files) {
      const error = !ALLOWED.includes(file.type) ? "Unsupported type"
                  : file.size > MAX_BYTES ? "Larger than 10 MB" : null
      this.items.push({ id: crypto.randomUUID(), file, progress: 0, tries: 0,
                        status: error ? "rejected" : "queued", error })
    }
    this.emit(); this.pump()
  }

  patch(id, change) { this.items = this.items.map(i => i.id === id ? { ...i, ...change } : i); this.emit() }

  pump() {
    while (this.running < this.limit) {
      const next = this.items.find(i => i.status === "queued")
      if (!next) return
      this.run(next)
    }
  }

  async run(item) {
    const ctrl = new AbortController()
    this.running++
    this.patch(item.id, { status: "uploading", ctrl, error: null })
    try {
      await uploadFile(item.file, { signal: ctrl.signal, onProgress: p => this.patch(item.id, { progress: p }) })
      this.patch(item.id, { status: "done", progress: 100 })
    } catch (e) {
      const tries = item.tries + 1
      if (e.name === "AbortError") this.patch(item.id, { status: "cancelled" })
      else if ((!e.status || e.status >= 500) && tries <= 2) {      // retry transient errors only
        this.patch(item.id, { status: "queued", tries })
      } else this.patch(item.id, { status: "failed", error: e.message, tries })
    } finally {
      this.running--; this.pump()
    }
  }

  cancel(id) { this.items.find(i => i.id === id)?.ctrl?.abort() }
  retry(id)  { this.patch(id, { status: "queued", tries: 0 }); this.pump() }
  remove(id) { this.cancel(id); this.items = this.items.filter(i => i.id !== id); this.emit() }
}

Edge cases and follow-upswhat gets probed

  • Validate by MIME type and extension on the client, and again on the server. The client check is only a courtesy; file.type can be spoofed.
  • Concurrency limit protects the browser (6 connections per host on HTTP/1.1) and the server.
  • Large files: never read them into memory on the server. Use chunked or multipart upload: the client splits the file (file.slice), uploads parts in parallel, and can resume after a failure. The common production design is a presigned URL so the browser uploads straight to object storage (S3) and your API only signs and records it. Protocols: tus, S3 multipart.
  • Image previews: URL.createObjectURL(file), and URL.revokeObjectURL on cleanup to avoid a memory leak.
  • Leaving the page while uploading: warn with beforeunload.
  • Duplicate files: detect by name + size + lastModified, or hash if needed.
  • Retry only safe failures (network, 5xx), never 4xx like 413 or 415.
interview edgeThe scoring points are: separation of queue logic from UI, progress with XHR, concurrency control, cancellation, per-file status and validation. Mention chunked or presigned uploads for big files and you have covered the senior follow-up.

// Insert taskId into column toCol at toIndex (index in the list WITHOUT the dragged card)
function moveTask(board, taskId, toCol, toIndex) {
  const from = Object.values(board.columns).find(c => c.taskIds.includes(taskId))
  if (!from) return board
  const fromIds = from.taskIds.filter(id => id !== taskId)
  const base = from.id === toCol ? fromIds : board.columns[toCol].taskIds
  const toIds = [...base.slice(0, toIndex), taskId, ...base.slice(toIndex)]
  return {
    ...board,
    columns: {
      ...board.columns,
      [from.id]: { ...from, taskIds: fromIds },
      [toCol]:   { ...board.columns[toCol], taskIds: toIds },     // wins when same column
    },
  }
}

Edge cases and follow-upswhat gets probed

  • Re-renders: memo on Column and Card, a stable onMove (useCallback), and normalised state: dragging one card re-renders only the two affected columns. Hundreds of cards in one column: virtualise it.
  • Touch devices: native HTML5 drag and drop does not work on touch screens. Use pointer events, or a library such as dnd-kit.
  • Keyboard and screen readers: drag and drop is inaccessible by itself. Offer a “Move to…” menu on each card, or use a library with a keyboard sensor (Space to lift, arrows to move, Space to drop) and live announcements.
  • Persisting order: sending the whole array each time races with other users. Better: PATCH /tasks/:id { columnId, afterId }, or fractional indexing (a position string/number between neighbours) so one row changes. Optimistic update with rollback if the request fails.
  • Drop indicator: show where the card will land; auto-scroll when dragging near an edge.
  • Concurrent edits (two users): last write wins per card, or push updates over a WebSocket and merge.
  • Undo: because moveTask is pure, keep a history stack of boards.

function Modal({ children, onClose, isTop }) {
  const ref = useRef(null)

  useEffect(() => {                                  // focus in on open, back out on close
    const opener = document.activeElement
    ;(ref.current.querySelector(FOCUSABLE) ?? ref.current).focus()
    return () => opener?.focus?.()
  }, [])

  useEffect(() => {
    if (!isTop) return                                // only the top modal reacts to the keyboard
    function onKey(e) {
      if (e.key === "Escape") return onClose()
      if (e.key !== "Tab") return
      const nodes = [...ref.current.querySelectorAll(FOCUSABLE)]
      if (!nodes.length) return e.preventDefault()
      const first = nodes[0], last = nodes[nodes.length - 1]
      if (e.shiftKey && document.activeElement === first) { e.preventDefault(); last.focus() }
      else if (!e.shiftKey && document.activeElement === last) { e.preventDefault(); first.focus() }
    }
    document.addEventListener("keydown", onKey)
    return () => document.removeEventListener("keydown", onKey)
  }, [isTop, onClose])

  return (
    <div className="backdrop" onMouseDown={e => e.target === e.currentTarget && onClose()}>
      <div ref={ref} role="dialog" aria-modal="true" tabIndex={-1} className="dialog">{children}</div>
    </div>
  )
}

    const q = deferred.trim().toLowerCase()
    let out = q ? rows.filter(r => columns.some(c => String(r[c.key]).toLowerCase().includes(q))) : rows
    if (sort.key) {
      const dir = sort.dir === "asc" ? 1 : -1

function LikeButton({ postId, initialLiked, initialCount }) {
  const [state, setState] = useState({ liked: initialLiked, count: initialCount })
  const pending = useRef(false)

  async function toggle() {
    if (pending.current) return                     // ignore clicks while a request is in flight
    pending.current = true
    const prev = state                              // snapshot for rollback
    const next = { liked: !prev.liked, count: prev.count + (prev.liked ? -1 : 1) }
    setState(next)                                  // optimistic
    try {
      await api.setLike(postId, next.liked)         // PUT, idempotent: sets a state, not "toggle"
    } catch {
      setState(prev)                                // rollback
      toast.error("Could not update your like")
    } finally {
      pending.current = false
    }
  }

  return (
    <button aria-pressed={state.liked} onClick={toggle}>
      {state.liked ? "♥" : "♡"} {state.count}
    </button>
  )
}

Say this“The socket lives in a hook with reconnect and backoff. Messages are kept in a reducer keyed by a client-generated id: I add my own message instantly as ‘sending’, and when the server echoes it back with the same clientId I flip it to ‘sent’ instead of adding a duplicate.”
function chatReducer(state, a) {
  switch (a.type) {
    case "local":    return [...state, { ...a.msg, status: "sending" }]
    case "incoming": {
      const i = state.findIndex(m => m.clientId && m.clientId === a.msg.clientId)   // my own echo
      if (i >= 0) return state.map((m, j) => j === i ? { ...a.msg, status: "sent" } : m)
      return state.some(m => m.id === a.msg.id) ? state : [...state, a.msg]            // dedupe
    }
    case "failed":   return state.map(m => m.clientId === a.clientId ? { ...m, status: "failed" } : m)
    default:         return state
  }
}

function useChat(roomId, user) {
  const [messages, dispatch] = useReducer(chatReducer, [])
  const [typing, setTyping]  = useState(false)
  const socketRef = useRef(null)

  useEffect(() => {
    let closed = false, tries = 0, timer
    function connect() {
      const ws = new WebSocket(`wss://example.com/rooms/${roomId}`)
      socketRef.current = ws
      ws.onopen = () => { tries = 0; ws.send(JSON.stringify({ type: "sync", after: lastId() })) }   // fetch what I missed
      ws.onmessage = e => {
        const m = JSON.parse(e.data)
        if (m.type === "message") dispatch({ type: "incoming", msg: m })
        if (m.type === "typing" && m.user !== user.id) { setTyping(true); clearTimeout(connect.t); connect.t = setTimeout(() => setTyping(false), 2000) }
      }
      ws.onclose = () => { if (!closed) timer = setTimeout(connect, Math.min(30000, 500 * 2 ** tries++) * (0.5 + Math.random() / 2)) }
    }
    connect()
    return () => { closed = true; clearTimeout(timer); socketRef.current?.close() }
  }, [roomId, user.id])

  const send = useCallback(text => {
    const clientId = crypto.randomUUID()
    dispatch({ type: "local", msg: { clientId, text, userId: user.id } })
    const ws = socketRef.current
    if (ws?.readyState === WebSocket.OPEN) ws.send(JSON.stringify({ type: "message", clientId, text }))
    else dispatch({ type: "failed", clientId })                       // or queue and flush on reconnect
  }, [user.id])

  return { messages, typing, send }
}

Dashboard widget: “Top 5 items” with pollingasked in a live-coding round

function useTopItems(url, intervalMs = 5000) {
  const [state, setState] = useState({ items: [], error: null, loading: true })

  useEffect(() => {
    let stopped = false, timer, failures = 0
    const ctrl = new AbortController()

    async function tick() {
      if (!document.hidden) {                                   // do not poll a background tab
        try {
          const res = await fetch(url, { signal: ctrl.signal })
          if (!res.ok) throw new Error("HTTP " + res.status)
          const data = await res.json()
          failures = 0
          if (!stopped) setState({ items: [...data].sort((a, b) => b.score - a.score).slice(0, 5), error: null, loading: false })
        } catch (e) {
          if (e.name === "AbortError") return
          failures++
          if (!stopped) setState(s => ({ ...s, error: e, loading: false }))   // keep the last good data visible
        }
      }
      if (!stopped) timer = setTimeout(tick, Math.min(60000, intervalMs * 2 ** failures))   // backoff while failing
    }
    tick()
    return () => { stopped = true; clearTimeout(timer); ctrl.abort() }
  }, [url, intervalMs])

  return state
}

function TopFive() {
  const { items, error, loading } = useTopItems("/api/items")
  if (loading) return <Skeleton />
  return (
    <section aria-live="polite">
      {error && <p role="alert">Showing last known data. Retrying…</p>}
      <ol>{items.map(i => <li key={i.id}>{i.name}: {i.score}</li>)}</ol>
    </section>
  )
}
  • setTimeout chain, not setInterval: the next poll is scheduled only after the previous one finishes, so slow responses never overlap or pile up.
  • Cleanup clears the timer and aborts the in-flight request. Missing it is the classic interval leak.
  • For real freshness prefer SSE or WebSocket; use ETag/If-None-Match so unchanged polls return a cheap 304.

function OtpInput({ length = 6, onComplete }) {
  const [digits, setDigits] = useState(() => Array(length).fill(""))
  const refs = useRef([])

  function update(next) {
    setDigits(next)
    if (next.every(Boolean)) onComplete?.(next.join(""))
  }
  function onChange(i, e) {
    const v = e.target.value.replace(/\D/g, "").slice(-1)            // one digit only
    const next = [...digits]; next[i] = v
    update(next)
    if (v && i < length - 1) refs.current[i + 1].focus()
  }
  function onKeyDown(i, e) {
    if (e.key === "Backspace" && !digits[i] && i > 0) refs.current[i - 1].focus()
    if (e.key === "ArrowLeft"  && i > 0)          refs.current[i - 1].focus()
    if (e.key === "ArrowRight" && i < length - 1) refs.current[i + 1].focus()
  }
  function onPaste(e) {
    e.preventDefault()
    const text = e.clipboardData.getData("text").replace(/\D/g, "").slice(0, length)
    if (!text) return
    const next = Array.from({ length }, (_, i) => text[i] ?? "")
    update(next)
    refs.current[Math.min(text.length, length - 1)].focus()
  }

  return (
    <div onPaste={onPaste}>
      {digits.map((d, i) => (
        <input key={i} ref={el => (refs.current[i] = el)} value={d}
               inputMode="numeric" autoComplete={i === 0 ? "one-time-code" : "off"} maxLength={1}
               aria-label={`Digit ${i + 1} of ${length}`}
               onChange={e => onChange(i, e)} onKeyDown={e => onKeyDown(i, e)} onFocus={e => e.target.select()} />
      ))}
    </div>
  )
}

▶ Key ideas: inputMode="numeric" opens the number pad, autoComplete="one-time-code" lets mobile browsers autofill from SMS, paste spreads across boxes, Backspace on an empty box jumps back. Using the index as a key is acceptable here because the boxes never reorder.

Countdown and stopwatch that do not driftasked in 3 loops

Say this“setInterval is not exact: it drifts and is throttled in background tabs. I store the target end time and compute the remaining time from Date.now() on each tick, so a late or skipped tick never loses time.”
function useCountdown(seconds) {
  const [endAt, setEndAt] = useState(null)
  const [left, setLeft]   = useState(seconds * 1000)

  useEffect(() => {
    if (!endAt) return
    const id = setInterval(() => {
      const remaining = Math.max(0, endAt - Date.now())
      setLeft(remaining)
      if (remaining === 0) { clearInterval(id); setEndAt(null) }
    }, 200)                                              // tick faster than 1 s; the maths keeps it exact
    return () => clearInterval(id)
  }, [endAt])

  return {
    secondsLeft: Math.ceil(left / 1000),
    running: endAt !== null,
    start:  () => setEndAt(Date.now() + left),
    pause:  () => { setLeft(Math.max(0, endAt - Date.now())); setEndAt(null) },
    reset:  () => { setEndAt(null); setLeft(seconds * 1000) },
  }
}

▶ Stopwatch is the same idea counting up from a startedAt. For display use padStart(2, "0") on minutes and seconds. Use performance.now() when you need a clock that cannot be changed by the user.

Quick checkanswers folded away

1. In an autocomplete, how do you stop an old slow response overwriting a newer one?

Abort the previous request in the effect cleanup (AbortController) and clear the debounce timer. If it cannot be aborted, ignore responses whose query no longer matches the current one.

2. Why onMouseDown instead of onClick on suggestion items?

The input’s blur fires before click and would close the list first. mousedown happens before blur.

3. Why cursor pagination for infinite scroll?

Items inserted at the top shift offset-based pages, causing duplicates or gaps. A cursor always continues after the last item seen.

4. Where should multi-step form values live?

In the parent, as one object, so steps can unmount without losing data. Validation and visibility are derived, not stored.

5. Why can’t you show upload progress with fetch?

fetch has no upload-progress event. Use XMLHttpRequest (xhr.upload.onprogress), or a stream-based approach in newer browsers.

6. Why is native HTML5 drag and drop a weak choice for a Kanban board?

No touch support and no keyboard accessibility. Use pointer events or dnd-kit, and offer a “Move to…” menu.

7. What must a modal do for accessibility?

role="dialog" with aria-modal and a label, move focus in, trap Tab, close on Escape, restore focus to the opener, and stop the background scrolling.

8. Why keep the toast store outside React?

So any code, even an API interceptor, can call toast.error(). Components subscribe with useSyncExternalStore.

9. How do you store comments for nested replies?

Flat with parentId, derive byId and childrenOf, render with a recursive component keyed by id.

10. Why is a countdown built on Date.now() and not a counter?

Intervals drift and are throttled in background tabs. Computing remaining time from a stored end time stays correct however late the ticks are.

11. setInterval or a setTimeout chain for polling?

A setTimeout chain: the next request is scheduled after the previous finishes, so requests never overlap, and backoff is easy.

12. Does hiding a button enforce permissions?

No. It is UX only. The server must authorise every request.
